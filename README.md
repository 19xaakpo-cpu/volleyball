# 🏐 Мішкобол

Волейбол мішками на двох у браузері. Вид збоку, посередині сітка. Мішки ходять, стрибають і присідають, а відбивати м'яч треба так, щоб він упав на половині суперника.

**Грати:** https://19xaakpo-cpu.github.io/volleyball/

## Режими

- **Удвох на одному пристрої:** клавіатура (WASD і стрілки) або сенсорні кнопки на телефоні.
- **Проти бота:** три рівні складності.
- **Гра по мережі:** один гравець створює кімнату й надсилає код або посилання, другий відкриває посилання.

## Правила

- М'яч упав на вашій половині — очко супернику.
- Одна сторона може торкнутися м'яча **не більше 3 разів поспіль**. Четверте торкання віддає очко супернику. Лічильник обнуляється, коли м'яч перелітає сітку.
- М'яч відскакує від стін, стелі та сітки.
- Удар у стрибку чи з розбігу сильніший. Присівши, мішок стає нижчим і ширшим.
- Гра до 7, 11, 15 або 21 очка, з перевагою щонайменше 2.

## Керування

|          | Лівий гравець | Правий гравець |
|----------|---------------|----------------|
| Ходити   | `A` `D`       | `←` `→`        |
| Стрибок  | `W`           | `↑`            |
| Присісти | `S`           | `↓`            |

`Esc`: пауза або меню · `M`: звук · `F`: на весь екран · `F3`: мережева діагностика

## Як влаштована мережева гра

Щоб не було відчутної затримки, використано **rollback netcode** — підхід із файтингів (GGPO):

1. Гравці з'єднуються **напряму через WebRTC** (PeerJS). Сервер PeerJS потрібен лише на кілька секунд, щоб гравці знайшли один одного.
2. Пристрої обмінюються **лише натисканнями клавіш**, кожне з номером кадру. Кожен пакет повторює ще не підтверджені кадри, тож втрата пакета нічого не ламає.
3. Свій хід гра виконує **одразу**. Хід суперника вона вгадує (вважає, що він тисне те саме, що й раніше).
4. Коли приходить справжній хід суперника і прогноз виявився хибним, гра **відкочується** до збереженого стану й непомітно перераховує кілька останніх кадрів.
5. Фізика **детермінована**: фіксований крок 60 Гц, лише прості арифметичні операції, без випадковостей. Однакові натискання дають бітово однаковий результат на всіх пристроях. Що секунду обидві сторони звіряють хеш стану.
6. Невелика затримка введення (1–4 кадри, залежно від пінгу) і вирівнювання темпу зменшують кількість відкатів.

## Розробка

```bash
npm install
npm run dev      # локальний сервер розробки
npm test         # тести фізики, бота і мережевої синхронізації
npm run build    # збірка в папку docs/ (її публікує GitHub Pages)
```

Структура:

- `src/sim/game.ts`: детермінована фізика і правила
- `src/net/rollback.ts`: rollback-сесія (не залежить від транспорту, тестується в Node)
- `src/net/peer.ts`: з'єднання через WebRTC (PeerJS)
- `src/bot.ts`: бот (симулює кілька варіантів удару наперед і вибирає найкращий)
- `src/render.ts`, `src/audio.ts`, `src/input.ts`, `src/main.ts`: графіка, звук, керування, меню

Режим перевірки мережі без другого гравця: `?netsim=150`, де 150 — імітований пінг у мс, а суперник — бот за імітованою мережею.
