# 🏐 Мішкобол

Волейбол мішками на двох у браузері. Вид збоку, посередині сітка. Мішки ходять, стрибають і присідають, а відбивати м'яч треба так, щоб він упав на половині суперника.

**Грати:** https://19xaakpo-cpu.github.io/volleyball/

## Режими

- **Удвох на одному пристрої:** клавіатура (WASD і стрілки) або сенсорні кнопки на телефоні.
- **Проти бота:** три рівні складності.
- **Виклик друга по мережі:** посилання-виклик містить код кімнати, ім'я того, хто викликає, локацію і довжину матчу. Друг бачить запрошення і натискає «Прийняти».
- **Турнір на 3–8 учасників:** кругова система, 1–4 кола. Буває на одному пристрої (люди й боти) або по мережі за посиланням: організатор координує, матчі різних пар ідуть одночасно, а таблицю всі бачать наживо.

## Вигляд і локації

- **Мішок:** колір, другий колір, візерунок (вишиванка, камуфляж, смужки…), лого, начинка (картопля, цибуля, буряк, яблука…), а також реакції рухами на вигране чи програне очко й гру. При розгромному рахунку (відрив від 4 очок) з мішка того, хто програє, висипається начинка.
- **М'яч:** готові дизайни або свій (візерунок, три кольори, лого). Кожна локація має свій м'яч за замовчуванням.
- **Локації:** пляж; корт із глядачами-мішками картоплі, цибулі й буряків; Лисичанськ (терикони і в'їзна стела «ЛИСИЧАНСЬК 1710» з гербом); Київ, Хрещатик (сталінки, Будинок профспілок, на табло вежі якого показується рахунок, каштани, ліхтарі, гірлянди; сітка стоїть на подвійній суцільній); метро «Хрещатик»; двір хрущовки з переповненими баками. У кожній своя «сітка»: волейбольна сітка, дерев'яний стовп, знак «Зупинку заборонено», покажчик «М», стовпчик із шин.
- **Тривога в Києві:** якщо в Києві повітряна тривога, гра на локації «Київ» автоматично переходить на станцію «Хрещатик» з оголошенням. Дані беруться з відкритого API ubilling.net.ua/aerialalerts.

## Правила

- М'яч упав на вашій половині — очко супернику.
- Одна сторона може торкнутися м'яча **не більше 3 разів поспіль**. Четверте торкання віддає очко супернику. Лічильник обнуляється, коли м'яч перелітає сітку.
- М'яч відскакує від стін і сітки, а вгорі може залетіти за екран. Де він, видно по тіні та стрілці.
- Удар у стрибку чи з розбігу сильніший. **Присісти** означає сильно підкинути м'яч угору.
- **Суперстрибок:** присісти і одразу стрибнути, мішок злітає в 1,8 раза вище. Від такого удару м'яч летить швидше й вище, і кожен суперудар (обох гравців) розганяє його ще більше, до ×1,6 за розіграш. Стоячи впритул до сітки, суперударом можна «гасити» м'яч униз (здалеку суперудар завжди йде вгору).
- **Ривок:** двічі швидко натиснути стрілку в один бік. Після нього мішок довше підводиться.
- **Подача:** м'яч висить над подаючим, доки його не вдарять. Звичайним стрибком його ледь дістати, суперстрибком легко. Через 10 секунд м'яч падає сам.
- Гра до 7, 11, 15 або 21 очка, з перевагою щонайменше 2.

## Керування

|          | Лівий гравець | Правий гравець |
|----------|---------------|----------------|
| Ходити   | `A` `D`       | `←` `→`        |
| Стрибок  | `W`           | `↑`            |
| Присісти | `S`  | `↓`            |
| Суперстрибок | `S`, потім `W` | `↓`, потім `↑` |
| Ривок | `D` `D` / `A` `A` | `→` `→` / `←` `←` |

`Esc`: пауза або меню · `M`: звук · `F`: на весь екран · `F3`: мережева діагностика

## Як влаштована мережева гра

Щоб не було відчутної затримки, використано **rollback netcode** — підхід із файтингів (GGPO):

1. Гравці з'єднуються **напряму через WebRTC** (PeerJS). Сервер PeerJS потрібен лише на кілька секунд, щоб гравці знайшли один одного.
2. Пристрої обмінюються **лише натисканнями клавіш**, кожне з номером кадру. Кожен пакет повторює ще не підтверджені кадри, тож втрата пакета нічого не ламає.
3. Свій хід гра виконує **одразу**. Хід суперника вона вгадує (вважає, що він тисне те саме, що й раніше).
4. Коли приходить справжній хід суперника і прогноз виявився хибним, гра **відкочується** до збереженого стану й непомітно перераховує кілька останніх кадрів.
5. Фізика **детермінована**: фіксований крок 60 Гц, лише прості арифметичні операції, без випадковостей. Однакові натискання дають бітово однаковий результат на всіх пристроях. Що секунду обидві сторони звіряють хеш стану.
6. Невелика затримка введення (1–4 кадри, залежно від пінгу) і вирівнювання темпу зменшують кількість відкатів.

## Розробка

```bash
npm install
npm run dev      # локальний сервер розробки
npm test         # тести фізики, бота і мережевої синхронізації
npm run build    # збірка в папку docs/ (її публікує GitHub Pages)
```

Структура:

- `src/sim/game.ts`: детермінована фізика і правила
- `src/net/rollback.ts`: rollback-сесія (не залежить від транспорту, тестується в Node)
- `src/net/peer.ts`: з'єднання через WebRTC (PeerJS)
- `src/bot.ts`: бот (симулює кілька варіантів удару наперед і вибирає найкращий)
- `src/tournament.ts`, `src/ui/tour.ts`: розклад, таблиця, локальний і мережевий турнір
- `src/cosmetics.ts`, `src/draw.ts`, `src/scenes.ts`: вигляд мішків і м'ячів, реакції, локації
- `src/alerts.ts`: стан повітряної тривоги в Києві
- `src/render.ts`, `src/audio.ts`, `src/input.ts`, `src/main.ts`: графіка, звук, керування, меню

Режим перевірки мережі без другого гравця: `?netsim=150`, де 150 — імітований пінг у мс, а суперник — бот за імітованою мережею.
